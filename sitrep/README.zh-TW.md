# sitrep

原名 reply-lens。sitrep 是 situation report 的縮寫，意思是「戰況簡報」。

> English: [README.md](README.md)

讓 Claude Code 的回覆比較好掃讀的 mod，仍是實驗版；從 marketplace 安裝：`claude plugin install sitrep@mango-mods`。

## 做什麼

- 不改系統提示。主對話的回覆夠長（程式碼區塊外 800 字以上）或有 2 個以上標題時，回合結束後把回覆切成編號行，請小模型（`haiku`、low effort、限時 20 秒）只回編號：哪行是結論、哪些是待決題目與選項、你要做的事、之後我做的事、哪幾段可以收合。mod 逐一檢查編號，用回覆原句組成結論框，模型寫不出回覆裡沒有的字；任何編號超出範圍或指錯種類的行，整份不收。等待時框的位置寫 `… 摘錄中`，失敗寫 `– 摘錄失敗：原因`；摘錄回來前新一輪已開始就作廢。
- 正文下面畫一個圓角結論框，標題旁一個灰字「摘錄」：
  - 標題疊在上框線：左邊是狀態（`? 等你決定`、`> 等你動手`、`! 卡住`、`~ 進行中`、`✓ 完成`），右邊是耗時。狀態照小模型挑的走：完成、卡住即使附了「你要做」也維持綠、紅；只有做到一半停下來等你才是「等你動手」。框線用暗一階的狀態色，只有兩種「等你」是黃。sitrep 的顏色全部用 Claude Code 的主題色名稱（`warning`、`error`、`success`、`inactive`…），跟著你的 `/theme` 走，淺色、daltonized 都一樣。框寬固定（終端寬減 4，最寬 88 欄）。
  - 接著是粗體的一句結論，下面緊接黃字「你要做」（要你親手做的事）。
  - 小模型挑出的段落（例如變更、驗證）從正文拿掉，在框裡變成一行摘要，點 `▸` 把那段放回正文原位。有題目時，正文標題含「決定」的那段（例如 `## 待你決定`）也一樣收進框，列成「利弊」，題目不在正文再寫一次。
  - 待你決定的題目列在框裡；點選項只把「題號. 選項」填進提示框，不送出。灰字「之後我」（模型接著做的事）排最後。
  - 較新的回覆有自己的框之後，舊框收成一行（`▸ ✓ 結論  8s`），點 `▸` 畫回完整框。
- prompt 上方一列：還有沒答的題目時是 `? N 題待決`，接第一題的題號與選項，聚焦這列（`Ctrl+X` 再按 `Tab`）後按選項字母（`a`、`b`…）選答，一樣只填進提示框；沒有題目但有要你做的事時是 `等你動手：…`（完工回覆附的建議不算）。有 survey 時讓位；跟其他 mod 的列（ctx-relay）疊著畫；較新的回覆兩者都沒有時消失。
- 沒摘錄的回合（短回覆、失敗或作廢），回合結束那列（`Baked for 3s`）換成灰色的 `– 本輪結束（無摘錄）` 或失敗原因，不假裝沒事。
- 子代理回報那列（收合時的 `Message from @…`）換成它回報的第一句。
- 背景工作（子代理、背景 shell…）結束的通知列，開頭換成狀態：灰 `✓` 完成、紅 `!` 失敗、灰 `–` 中止。
- 那一輪派出去的背景子代理會列在結論框裡（`⠋ Explore  描述  執行中 42s`，有子代理在跑時轉圈字形和已跑時間每 250ms 更新），跑完自動換成 `✓` 和耗時；引擎自己的那幾列照原樣。
- 狀態 pane（實驗中，另案重新設計）：`/sitrep-pane` 開或關，不會自己打開。內容由上而下：需要你（每題一塊黃底，聚焦後按字母選答）、進行中（子代理與背景工作＋已跑時間）、任務（引擎的任務清單，✓／▸／○）、證據（最近一次驗證摘要拆成小標籤，下面列「驗證」段前 4 行；沿用到下一次驗證）、變更（這個 session 改過的檔逐檔 +/−，其餘收成「不是這次改的 N 檔」）。pane 開著時題目只在 pane 選：prompt 上方那列不畫，結論框換成回覆底下一行結論。
- 子代理回報展開時，拿掉開頭給模型看的 `[Subagent hand-back] …` 框架說明；派了背景子代理的那一輪，不畫引擎的「Waiting for N background agents」列（結論框裡已有子代理那一行）。
- 子代理 pane：`/agents-info` 開或關，不會自己打開。最上一行是總數、進行中數量和累計輸出 token，下面分「進行中」「已結束」（最近 10 個）。每個子代理兩行：狀態符號（跑的時候轉圈）、類型、描述、耗時；下一行灰字是 model、effort、最近一次請求的 context、請求次數、輸出 token。子代理自己派的、workflow 派的也列進來。不算成本也不顯示 context 百分比：引擎沒給各 model 的上限和價格。沒有能放 pane 的畫面時（雲端 session、`claude -p`），`/agents-info` 改用文字回同一份清單。子代理在跑、pane 沒畫出來時，prompt 上方那列多一行 `⠋ 子代理 2 個進行中 · 輸出 12k`；tmux 預設不是 fullscreen，pane 會疊在提示框上方，平常看這行就夠。
- 回覆裡的 ASCII 圖（沒標語言或標 `text` 的程式碼區塊，至少 2 行、且占非空白行三成以上帶框線字元、箭頭，或純 ASCII 的 `+--`、`|--`；有中文句讀或像 Markdown 清單開頭的行不算，所以交接草稿裡寫 `A → B` 的仍是一般程式碼區塊）畫在灰底區塊裡，上方一行灰字「圖」，不被前後大段文字蓋過。
- 回覆裡的 ```dot 區塊照 ASCII 圖的方式畫原文，標籤另附粗算的節點與邊數。不畫成圖片：Claude Code 在 tmux 裡關掉圖片，而這個 mod 平常就在 tmux 裡用。
- 只改畫面：存下來的訊息不變。

狀態符號：`?` 黃＝等你決定、`>` 黃＝等你動手、`!` 紅＝卡住、`~` 部分完成、`✓` 完成、`–` 沒有摘錄。

## 試用

```bash
claude --plugin-dir ~/projects/mango-mods/sitrep
```

## 已知限制

- 回合結束那列沒有輪次編號，「無摘錄」提示用耗時（±3 秒）對回 `turn.complete`；耗時很接近的兩輪可能對錯。短回合引擎可能不畫那列，所以結論條改畫在回覆裡。
- 結論框用回覆正文的雜湊對回回覆：`turn.complete` 的 answer 是這一輪最後一段文字，所以回覆被工具呼叫切成好幾段時，框畫在最後一段下面。短到不摘錄的回覆沒有框，它派出的子代理只出現在 prompt 上方那行和 `/agents-info`。
- 摘錄只挑原句：回覆裡沒有一行講清楚的結論出不來；沒寫成「題目＋選項行」的決定不會變成按鈕；前幾輪沒答的題目，新回覆沒重寫就不會再列。
- 每則長回覆多一次 `haiku` 請求。
- ctrl+o 看不到原文：回覆那列不會告訴 mod 現在是不是 ctrl+o 畫面，所以那裡一樣畫成結論框。要看收起來的段落，點 `▸` 放回正文。
- 摘錄在回覆結束幾秒後才回來，收合的段落會在那一刻一起離開正文，正文仍會往上縮一次。
- `/agents-info` 在 `agent.spawn` 回傳 id 時才記下子代理；workflow 的遠端 agent 沒有 id，不會列出。`turn.complete` 一直沒來的子代理會轉圈到 session 結束。
- focus 模式（`/focus`）下引擎會藏掉背景工作的通知列，那裡看不到狀態符號。
