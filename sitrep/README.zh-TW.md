# sitrep

讓 Claude Code 的長回覆一眼看得懂的 mod。sitrep 是 situation report 的縮寫，意思是「戰況簡報」。

> English: [README.md](README.md)

長回覆常把你要的東西埋在中間：到底成功沒有、Claude 要你做什麼。sitrep 在每則長回覆下面畫一個框：狀態、一句結論、你要做的事、等你回答的題目，題目可以用鍵盤選答。框裡每個字都是從回覆原文抄的：小模型只挑行號，所以框裡不會出現回覆沒說的話。

## 標籤與語言

mod 自己的標籤（狀態、提示框上方那列、pane 標題）預設是英文。把 `language` 設成 `zh-TW` 就換成繁體中文，在 `/config` 的 sitrep 那列設，或在 shell 執行：

```bash
echo '{"language": "zh-TW"}' | claude plugin configure sitrep@mango-mods --values-stdin
```

框裡的內容一律是回覆原句，所以跟著對話的語言走。下面列的標籤是 `zh-TW` 的寫法。

## 核心功能

- **摘錄。** 主對話的回覆夠長（程式碼區塊外 800 字以上）或有 2 個以上標題時，回合結束後把回覆切成編號行，請 `haiku`（low effort、限時 20 秒）只回行號：哪行是結論、哪些是題目與選項、你要做的事、Claude 接著做的事、哪幾段可以收合。mod 逐一檢查行號，用那些原句組成結論框；任何行號超出範圍或指錯種類的行，整份不收。不改系統提示。
  - 認得的標題會改寫模型挑的行號：`## 結果`／`Result`／`Summary` 標題下第一行是結論；`## 待你決定`／`Decisions` 段裡連號的 `A.`／`B.`（或 `選項 A：`）行是一題的選項（前一行是題目，後面寫「建議」／recommend 的那行標推薦）；變更、驗證、風險這類段落的第一行是該段摘要。狀態、你要做、之後我照舊由模型判斷。
  - 等待時框的位置寫 `… 摘錄中`，失敗寫 `– 摘錄失敗：原因`；摘錄回來前新一輪已開始就作廢。
- **結論框**，畫在回覆下面，標題旁一個灰字「摘錄」：
  - 標題疊在上框線：左邊是狀態（`? 等你決定`、`> 等你動手`、`! 卡住`、`~ 進行中`、`✓ 完成`），右邊是這一輪的耗時。完成、卡住即使附了「你要做」也維持原本的顏色；只有做到一半停下來等你才是「等你動手」。只有兩種「等你」是黃色。
  - 接著是粗體的一句結論，下面緊接黃字「你要做」。
  - 小模型挑出的段落（例如變更、驗證）從正文拿掉，在框裡變成一行摘要，標籤是藍色粗體，點 `▸` 把那段放回正文原位。有題目時，標題講到決定的那段（`## 待你決定`、`## Decisions`）也從正文拿掉，題目不在正文再寫一次；那段其餘的行（利弊、建議的理由）直接畫在框裡題目底下，不用按 `▸`。
  - 接著是題目，一個選項一行、不截斷；點選項只把「題號. 選項」填進提示框，不送出。沒列選項的題目只畫題目（直接打字回答）。挑到的表格列，格子用 ` · ` 接起來。灰字「之後我」（Claude 接著做的事）排最後。
  - 較新的回覆有自己的框之後，舊框收成一行（`▸ ✓ 結論  8s`），點 `▸` 畫回完整框。
  - 顏色全部用 Claude Code 的主題色名稱（`warning`、`error`、`success`、`inactive`…），跟著你的 `/theme` 走，淺色、daltonized 都一樣。框寬是終端寬減 4，最寬 88 欄。
- **提示框上方那一列。** 還有沒答的題目時是 `? N 題待決`，接第一題的選項；聚焦這列（`Ctrl+X` 再按 `Tab`）後按選項字母（`a`、`b`…），一樣只填進提示框。沒有題目但有要你做的事時是 `等你動手：…`（完工回覆附的建議不算）。有 survey 時讓位；跟其他 mod 的列（ctx-relay）疊著畫；較新的回覆兩者都沒有時消失。
- **不假裝沒事。** 沒摘錄的回合（短回覆、失敗或作廢），回合結束那列（`Baked for 3s`）換成灰色的 `– 本輪結束（無摘錄）` 或失敗原因。

狀態符號：`?` 黃＝等你決定、`>` 黃＝等你動手、`!` 紅＝卡住、`~` 進行中、`✓` 完成、`–` 沒有摘錄。

## 附加功能

- 子代理回報那列（收合時的 `Message from @…`）換成它回報的第一句；展開時拿掉開頭給模型看的 `[Subagent hand-back] …` 框架說明。
- 背景工作（子代理、背景 shell…）結束的通知列，開頭換成狀態：灰 `✓` 完成、紅 `!` 失敗、灰 `–` 中止。
- 那一輪派出去的背景子代理列在結論框裡（`⠋ Explore  描述  執行中 42s`，每 250ms 更新），跑完換成 `✓` 和耗時。這種回合不畫引擎的「Waiting for N background agents」列。
- sitrep 不另外畫子代理清單。Claude Code 自己會在 status line 下方列出進行中的子代理，fullscreen 和一般模式都有；想改每列顯示的內容，設定 `subagentStatusLine`。
- `/sitrep-pane` 開關狀態 pane（實驗中）：需要你（題目，按字母選答）、進行中（子代理與背景工作）、任務（引擎的任務清單）、證據（最近一次驗證拆成小標籤）、變更（這個 session 改過的檔，附 +/−）。pane 開著時題目只在 pane 選：提示框上方那列不畫，回覆底下只留一行結論。
- 回覆裡的 ASCII 圖（沒標語言或標 `text` 的程式碼區塊，至少 2 行、且占非空白行三成以上帶框線字元、箭頭，或純 ASCII 的 `+--`、`|--`）畫在灰底區塊裡，上方一行灰字「圖」。有中文句讀或像 Markdown 清單開頭的行不算，所以文字裡寫 `A → B` 的仍是一般程式碼區塊。
- ```dot 區塊用同樣方式畫原文，標籤另附粗算的節點與邊數。不畫成圖片：Claude Code 在 tmux 裡會關掉圖片。
- 只改畫面：存下來的訊息不變。

## 試用

```bash
git clone https://github.com/mangow314/mango-mods
claude --plugin-dir ./mango-mods/sitrep
```

## 已知限制

- 每則長回覆多一次 `haiku` 請求，走你自己的 Claude Code 帳號。
- 摘錄只挑原句：回覆裡沒有一行講清楚的結論出不來；沒寫成「題目＋選項行」的決定不會變成按鈕；前幾輪沒答的題目，新回覆沒重寫就不會再列。哪行算結論、哪行算「之後我」是模型的判斷，可能挑偏。
- 回合結束那列沒有輪次編號，「無摘錄」提示用耗時（±3 秒）對回 `turn.complete`；耗時很接近的兩輪可能對錯。短回合引擎可能不畫那列，所以結論條改畫在回覆裡。
- 結論框用回覆正文的雜湊對回回覆。回覆被工具呼叫切成好幾段時，框畫在最後一段下面。短到不摘錄的回覆沒有框，它派出的子代理只出現在 Claude Code 自己在 status line 下方的清單。
- ctrl+o 看不到原文：回覆那列不會告訴 mod 現在是不是 ctrl+o 畫面，所以那裡一樣畫成結論框。要看收起來的段落，點 `▸` 放回正文。
- 摘錄在回覆結束幾秒後才回來，收合的段落會在那一刻離開正文，正文會往上縮一次。
- 結論框和狀態 pane 在 `agent.spawn` 回傳 id 時才記下子代理；workflow 的遠端 agent 沒有 id，不會列出。`turn.complete` 一直沒來的子代理會轉圈到 session 結束。
- focus 模式（`/focus`）下引擎會藏掉背景工作的通知列，那裡看不到狀態符號。
